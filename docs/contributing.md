# Как вести работу в репозитории

Что здесь: коммиты, ветки, мёрдж в `main`, хуки, версия.

Чего здесь нет: процесса работы агента ([AGENTS.md](../AGENTS.md)).

---

## Коммиты

Формат — [Conventional Commits](https://www.conventionalcommits.org/), описание на русском:

```
<тип>(<scope>): <краткое описание>
```

* `<тип>` — из таблицы ниже.
* `<scope>` — модуль пакета: `process`, `session`, `transport`, `config`, `cli`; или `docs`.
  Опускается, если правка общая (`chore: …`).
* Описание — с маленькой буквы, без точки в конце; говорит, что стало иначе.
* Тело опционально: через пустую строку — «почему».
* Без трейлеров `Co-Authored-By`, в том числе в merge-коммитах и от ИИ-ассистентов.

| Тип | Когда |
|---|---|
| `feat` | новая функциональность |
| `fix` | исправление бага |
| `refactor` | изменение кода без смены поведения |
| `perf` | ускорение без смены поведения |
| `docs` | только документация |
| `style` | форматирование, без смены логики |
| `build` | сборка, окружение, зависимости |
| `test` | тесты |
| `chore` | рутина, не попадающая в остальные типы |

## Ветки

* `main` — единственная долгоживущая ветка; остальное — `<тип>/<кратко>` от `main`, тип из
  таблицы.
* Мелочь — прямо в `main`: одна атомарная правка без смены поведения (`docs`, `style`).
* После каждого коммита `just check` зелёный.
* Пока ветка не опубликована, служебные коммиты схлопываются в осмысленные ребейзом.

## Мёрдж в `main`

* `git merge --no-ff`: не squash и не fast-forward.
* Сообщение merge-коммита — заголовок в формате Conventional Commits по итогу ветки, тело — что
  и зачем, затем какие проверки пройдены (`just check`, ручной прогон в Maya).

## Хуки

`just install-hooks` один раз направляет git на `hooks/` (`core.hooksPath`).

| Хук | Что гоняет |
|---|---|
| `pre-commit` | `uv lock --check`, `ruff format --check`, `ruff check`, `mypy` |

Хуку нужен `uv` на PATH. Новый хук добавляется с исполняемым битом:
`git add --chmod=+x hooks/<хук>`. Аварийный выход — `git commit --no-verify`.

## Версия и релиз

Версия — `[project].version` в `pyproject.toml`, выпуск — тег `vX.Y.Z` на merge-коммите в
`main` и GitHub Release с колесом этого тега: плагины ставят пакет только готовым колесом
([README.md](../README.md), «Установка»).

```powershell
uv build --wheel -o dist
gh release create vX.Y.Z dist/maya_harness-X.Y.Z-py3-none-any.whl
```

Push и релиз — только руками разработчика: рецептов для них нет.
