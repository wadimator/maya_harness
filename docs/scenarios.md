# Сценарии и контроли

Что здесь: как прогнать проверки плагина в настоящей Maya командой `maya-harness run` и как
написать для неё сценарий.

Чего здесь нет: что проверяют сценарии конкретного плагина — это в его документации;
устройство раннера — в docstring `src/maya_harness/scenarios.py` и `src/maya_harness/pool.py`.

## Настройки

```toml
[tool.maya_harness]
reload = ["My_Plugin", "_live"]           # пакеты, которые выгружаются перед каждым прогоном

[tool.maya_harness.scenarios]
dir = "dev_tools/maya_checks"             # сценарии check_*.py; первым в sys.path Maya
runs = "dev_tools/maya_checks/runs.toml"  # таблица прогонов: что гонят `run all`, `scenarios` и `controls`
```

Таблица прогонов — TOML, по записи на прогон:

```toml
[[run]]
scenario = "check_bake"
seconds = 34                # замер: `all` гонит от самого долгого, и Maya кончают почти разом

[[run]]
scenario = "check_bake"
control = "no_round"
expect = "film.whole_frames" # ожидаемый первый провал контроля
seconds = 8
```

Сценарий без контроля — запись без `control` и `expect`; контроль — с обоими.

## Запуск

```powershell
just maya run check_floor                    # один сценарий
just maya run check_pair check_scale         # несколько, каждый — в первой свободной Maya
just maya run all                            # все записи таблицы прогонов
just maya run scenarios                      # сценарии без контролей
just maya run controls                       # только контроли
just maya run --jobs 1 all                   # в одной Maya
just maya run check_window control=busy      # один контроль
just maya run check_bake section=film        # одна секция сценария
```

`just maya` — рецепт `uv run --frozen --exact maya-harness {{ arguments }}` плагина.

* `run` поднимает свои Maya — каждую со своим сеансом на своём скрытом рабочем столе, гонит
  сценарии и закрывает каждую, как только для неё не осталось прогонов. Сеансы `run` не видны
  `status`, `exec` и `stop`: они живут, пока идёт прогон.
* `--jobs N` — сколько Maya сразу, по умолчанию 3, но не больше, чем прогонов. С `--visible` —
  одна. Сценарии идут в порядке перечисления, `all`, `scenarios` и `controls` — от самого
  долгого; запуск Maya стоит ~15 с, поэтому одна Maya гонит прогоны, пока они есть.
* Каждая Maya пула берёт слот машины ([README.md](../README.md), «Сколько Maya
  одновременно»): при `--jobs 3` и двух свободных слотах поднимаются две, третья — когда слот
  освободится, если прогоны ещё остались; не осталось — перестаёт ждать. `--slot-wait СЕК` —
  сколько ждать; не дождавшаяся Maya выбывает, код `2` — только если не поднялась ни одна.
* Строки хода: `maya1 pid <N>: started`, `maya1: ready in <N> s`, `maya1: <прогон>` при взятии
  прогона.
* Каждая Maya идёт с пониженным приоритетом и, если логических CPU больше 8, без первых четырёх.
  Больше 4 Maya на 8 ядрах только тормозят друг друга — `run` об этом предупреждает.
* Контроль — `<сценарий> control=<значение>` из таблицы прогонов; он гонит только свою секцию.
  Секция — `<сценарий> section=<имя>`. Другие параметры, контроль или секцию у `all`,
  `scenarios`, `controls` или у нескольких сценариев `run` отклоняет до запуска Maya;
  неизвестную секцию — сам сценарий, списком своих секций.
* Отчёт каждого прогона печатается JSON-ом целиком, когда прогон кончился, со строкой прогресса
  `[5/20] maya2 check_floor ok 61.0 s`; в конце — сводка в порядке прогонов: сценарий, Maya,
  время, итог. `--json` — сводка одной JSON-строкой на stdout, отчёты — в stderr.
* Код выхода: `0` — всё прошло; `1` — сценарий упал, контроль не покраснел своим ожидаемым
  провалом или до прогона не дошло («not run»); `2` — ничего не запущено (отказ в аргументах,
  нет настроек, ни одна Maya не поднялась).
* Упавшая или зависшая дольше таймаута (900 с) Maya проваливает свой прогон — с путём к логу и
  заголовками окон — и выходит из прогона; остальные доделывают очередь. Лог Maya, у которой всё
  прошло, удаляется.
* Ctrl+C закрывает все Maya прогона: каждая живёт в job object процесса `maya-harness`.

### Отладка в одной Maya

Без старта Maya на каждую правку: `maya-harness start`, затем правка и
`maya-harness run --url <адрес> <сценарий> section=<имя>` сколько нужно, в конце
`maya-harness stop`. Сценарий и пакеты из `reload` перечитываются с диска на каждый прогон;
`sys_path` и свои плагины Maya — нет: их правка требует нового `start`.

## Контроль

Контроль — заведомая поломка в коде сценария и ожидаемый первый провал: запись таблицы прогонов
с `control` и `expect`. Контроль проходит, только если имя первого провала — до первого `:` —
точно равно ожидаемому: провал в другом месте значит, что поломка задела не то, что держит
проверка, а префикс `fingers.gloves` совпал бы с `fingers.gloves_rad`. `all` гонит контроли
сам, `controls` — только их, `scenarios` — без них; без записи в таблице `run` контроль не
запустит.

## Как написать сценарий

* Модуль `check_<имя>.py` в каталоге сценариев с функцией `run(control="", section="")`, которая
  возвращает словарь отчёта со списком `failures`; пустой список — проверка прошла. Параметры
  приходят строками. Отчёт уходит JSON-ом: что не JSON, становится `str()`.
* Сценарий — секции: функции `(check: Check) -> None`, docstring секции — перечень её случаев.
  `SECTIONS` — секции в порядке прогона, `CONTROLS` — контроль → его секция; `run` зовёт
  `run_sections(SECTIONS, CONTROLS, control, section)`. Ожидания —
  `check.expect(имя, факт, ожидание)` и `check.fail(имя, текст)`; время секций — в
  `report["sections"]`, исключение секции — провал `<секция>.raised` с трейсбеком в отчёте, и
  следующие секции идут.

  ```python
  from maya_harness.inmaya import Check, no_prompts, run_sections, work_dir
  ```

* Секция независима и готовит сцену сама: любая идёт одна (`section=`, контроль).
* Фикстура нескольких секций — функция сценария под `functools.cache`: модули перезагружаются на
  каждый прогон, кеш между прогонами не живёт.
* Промежуточные файлы — в `work_dir()`: каталог сеанса Maya. Вне Maya maya_harness `work_dir()`
  падает: сценарий начинает с новой сцены и выбросил бы сцену художника. Общий модуль сценариев
  плагина зовёт его при импорте — так отказывает и он.
* Диалог на скрытом рабочем столе вешает прогон: операции, которые могут спросить о потерянном
  файле, — под `no_prompts()`.
* Перед прогоном выгружаются модули `check_*` и пакеты из `reload`: разовая проба — тоже модуль
  `check_*`, иначе выполнится старый код. В коммит пробы не идут.
* Новая проверка принимается контролем: сломай то, что она держит, и убедись, что она
  покраснела.

`maya_harness.inmaya` попадает в Maya копией пакета в `pylib/` сеанса, а не из `.venv`
проекта: в коде сценария он импортируется и без `sys_path`.
