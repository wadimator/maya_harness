# Диагностика

Что делать, когда Maya не поднялась, вызов висит или ответ странный. Устройство —
[design.md](design.md).

## Сначала

`maya-harness doctor` — Maya, `.mod`, пути в нём, версия модуля dcc-mcp. С
`MAYA_HARNESS_DCC_MCP_PATCH`, указывающей на клон DCC_MCP, — ещё и наложен ли его патч.

## Грабли

* **Модальный диалог вешает вызовы.** Диалог на скрытом рабочем столе не видно, а Maya не
  берёт вызовов, пока на него не ответят. `exec` и `run` обрывают такой вызов за ~2 с и
  печатают заголовок диалога: код 1, если код ушёл в Maya (он продолжится после ответа), и 2,
  если Maya уже стояла на диалоге и оборвалось соединение. Maya остаётся на диалоге: убрать её —
  `stop`, он тоже печатает заголовки окон Maya и убивает её сразу. Таймер простоя при диалоге
  срабатывает: забытая Maya закроется сама через `--ttl`. `start`, не дождавшись сервера, тоже
  печатает заголовки окон Maya. Код, который может спросить пользователя (`cmds.file` без
  `force=True`, экспорт поверх существующего файла), — с флагами, которые не спрашивают.
* **Плагин Maya из временного каталога ставит Maya на «Untrusted Plugin Loading».** Плагин
  грузить из каталога `MAYA_PLUG_IN_PATH` (из `plug_in_path` проекта), а не из временной копии:
  из другого каталога Maya спрашивает, доверять ли ему. Отключить вопрос из кода нельзя —
  запись настроек безопасности (`TrustCenterPathOption`, `SafeModeAllowedlistPaths`) сама
  открывает модальный диалог.
* **`maya-busy` до таймаута.** Maya открывает или сохраняет сцену дольше таймаута вызова
  (900 с). Открытие, вставшее на диалоге, таймаута не ждёт: вызов обрывается с заголовком
  диалога.
* **Ctrl+C не убивает Maya** — значит, раннер запущен из Git Bash: процесс оттуда Ctrl+C не
  получает. Проверять из PowerShell.
* **`exec` говорит «no running Maya of the project»**, хотя Maya запущена: сеанс выбирается по
  корню проекта, а не по имени. Maya, поднятая из другого worktree, — чужая; адрес можно
  передать явно: `exec <url> -c ...`.
* **`start` или `run` не поднимают Maya** — ждут свободный слот машины; кто держит слоты,
  написано в stderr и в `status`. Освободить — `maya-harness stop <url>`; не ждать дольше — `--slot-wait СЕК`.
* **Новые пути из `[tool.maya_harness]` не видны** — `sys_path` и `plugins` применяются при
  `start`. Перезапусти Maya.

## Где смотреть

* **Каталог сеанса** — `%TEMP%\maya_harness_<project>_<pid>_*`, путь — поле `dir` в `status --json`:
  * `state.json` — проект, pid раннера и Maya, адрес, время старта, TTL;
  * `work\startup.txt` — докуда дошёл `userSetup.py`; трейсбек — если не загрузился плагин;
  * `work\dcc_mcp_bootstrap.jsonl` — этапы загрузки dcc-mcp;
  * `work\last_call` — время последнего `exec`, от него считается простой;
  * `work\in_call` — идущий вызов: pid ждущего процесса и с какого времени; по нему `status`,
    `stop` и ожидание слота пишут `busy`;
  * `app\` — `MAYA_APP_DIR` сеанса, `appdata\` — его `APPDATA`.

  Каталог Maya, убитой `stop`, `stop` удаляет сразу; если `stop` сказал `still running`,
  каталог остаётся. Каталог Maya, закрытой иначе (таймер простоя, падение), удаляет следующий
  `start`.
* **Лог dcc-mcp** — `%LOCALAPPDATA%\dcc-mcp\log\dcc-mcp-maya.<pid>.<дата>.log`. Если Maya не
  поднялась, `start` печатает пути к её логам.
* **«Maya exited before its dcc-mcp server started» или таймаут старта** — статус
  `userSetup.py` и этапы bootstrap из сообщения, затем путь к `.mod` и абсолютные пути в нём
  (`doctor`).
